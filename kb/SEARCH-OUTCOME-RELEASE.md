# Update the installed KB instructions in a future release

This is a future operator procedure. The implementation and checks are local.
No installed instruction path has been verified, and no production change is
authorized by this document.

1. Obtain separate authorization for the behavior-changing release and its
   documented model-quality evaluation. Keep sends and provider tools read-only.
2. Locate the installed Hermes `SOUL.md` and the installed Buttons Bebe
   `ticket-processor` and `support-agent` instructions. Verify the active paths
   with the operator. CD deploys KB and processor code, but does not deploy
   `hermes/`.
3. Preserve the current installed instructions and the matching current KB and
   processor versions for rollback. Review the repository instruction changes
   alongside the KB answer-shape change.
4. Update the installed consuming instructions before activating the new MCP
   response. During this transition, accept the former passage list and the new
   object. For the object, read passages only from `results`. Health codes and
   `operator_action` stay internal. An unavailable board may still contain active
   owner overrides. Hold policy-dependent answers for a specific staff check.
5. Activate the coordinated KB and processor version through the authorized
   release process. Keep the single read-only `search_kb` tool. Verify the actual
   installed instructions, actual serialized response, and synthetic drafting
   behavior. Healthy empty results must differ from unavailable retrieval.
6. Evaluate conflicting current policy and a learned example. Policy must govern
   the answer regardless of score. Check ordinary gaps without HIGH priority,
   sensitive requests with urgency, and no generic fallback replies. Run the
   documented 48-scenario model-quality gate before considering release complete.
7. After verification, remove the temporary instruction acceptance of the former
   list response. The repository instructions describe only the new object.

To roll back, restore the former KB and processor code while the installed
instructions still accept both shapes. Verify the former MCP list response.
Then restore the preserved installed instructions. Do not restore instructions
that understand only lists while the MCP service still returns objects.
