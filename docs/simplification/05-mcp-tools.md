**Interface/seam:** two localhost HTTP MCP services (`buttonsbebe_gorgias` :8079, `buttonsbebe_redo` :8078, both `/mcp` endpoints — `hermes/config.example.yaml:187-199`) consumed only by the Hermes CLI; systemd units set `streamable-http` transport (`tools/buttonsbebe-gorgias-mcp.service:8-10`). **Job:** expose GET-only Gorgias/Redo reads to Hermes as annotated read-only MCP tools (`ToolAnnotations(readOnlyHint=True, …)` — `tools/gorgias_mcp.py:72`, `tools/redo_mcp.py:102`), with hard input validation, sanitized/normalized payloads, and fail-soft error dicts so a provider failure degrades a draft instead of crashing the brain. The `hermes/` dir is a doc-only mirror of the VPS-side Hermes home, not runtime code.

**Answers to the specific questions (evidence expanded below):**

- **(a) Protocol layer hand-rolled?** No. Both services import the official MCP Python SDK's `FastMCP` (`tools/gorgias_mcp.py:23`, `tools/redo_mcp.py:20`, sibling `kb/scripts/kb_mcp_server.py:30`). Measured hand-rolled JSON-RPC/framing/dispatch LOC across `gorgias_mcp.py` + `redo_mcp.py` + `_common.py`: **0**. Per-service boilerplate is ~12 lines (env config + `FastMCP(...)` + `mcp.run(transport=…)` — `tools/gorgias_mcp.py:29-51,119-120`). Nothing duplicated to move into `_common.py`; the SDK already owns the protocol.
- **(b) `_common.py`:** hand-rolled `.env` parser yes (25 LOC, `tools/_common.py:9-33`); HTTP client is **not** hand-rolled — `requests==2.32.4` is a declared direct dep (`tools/requirements.txt:4`); timeouts yes (20 s, `tools/gorgias_mcp.py:64`, `tools/redo_mcp.py:43`); retries: none (single-shot, deliberate). See Reinvented wheels.
- **(c) `gorgias_content.py`:** used only by `tools/gorgias_mcp.py` (import at `gorgias_mcp.py:27`, calls at `:87,:103`) and its two tests (`tools/test_gorgias_content.py:2`, `tools/test_gorgias_read_contract.py:6,18`). It exists as a separate file so tests can import curation logic **without** importing `gorgias_mcp.py`, which loads credentials at module import time (`gorgias_mcp.py:44-49`) — a deliberate testability seam, not a wheel.
- **(d) Three Gorgias adapters:** see Duplication map / Rejected — recommendation is **do not extract**; they do not even agree on URL/error/auth shapes today, and the isolation is the safety boundary.
- **(e) Launchers:** reason IS documented in-file ("space-free path, because the tools folder path contains a space" — `tools/run-gorgias.sh:2-3`); they are load-bearing in the CD manifest (`deploy/cd/source_release.py:33` lists both as REQUIRED_FILES) and units point at `/root/*-mcp-run.sh` (`tools/buttonsbebe-gorgias-mcp.service:11`).
- **(f) HTTP server:** not stdlib `http.server` — FastMCP's streamable-http transport runs on uvicorn/starlette (`uvicorn==0.50.2`, `starlette==1.3.1` in `tools/requirements.lock:675,:642`), process-supervised by systemd `Restart=on-failure, RestartSec=3` (`tools/buttonsbebe-gorgias-mcp.service:12-13`). Server robustness is the SDK's problem and the SDK is boring/standard.
- **(g) `hermes/` mirror:** documented as a copy in AGENTS.md:98, but **no sync check exists** (release gate scan roots at `tools/verify_release.sh:85` exclude `hermes/`; no workflow or script references it — only `tools/ops/recovery_policy.py:18` lists `/root/.hermes/SOUL.md` as a *recovery* path, not a sync check). It has already drifted twice — see Reliability risks.

## Duplication map

Within module:

1. **`_get()` twins** — `tools/gorgias_mcp.py:59-69` vs `tools/redo_mcp.py:37-49`: same 11-line shape (config check → `requests.get(BASE+path, params, timeout=20)` → `{"error": f"<Provider> API {status}", "detail": text[:200]}` → `{"error": "request failed", "detail": repr(e)[:200]}`). Differ only in auth (Basic tuple vs Bearer header). ~12 LOC theoretically shareable via `_common`. **Recommend keeping separate** — each integration being "its own module" is the stated architecture (`tools/README.md:3-6`), and 11 boring lines per side is cheaper than coupling the two safety-domains' auth styles.
2. **`_clean` ×2** — `tools/gorgias_mcp.py:35-36` ≡ `tools/_common.py:15-17`. Actionable (P3, trivial).
3. **systemd units ×2** — `tools/buttonsbebe-gorgias-mcp.service` and `tools/buttonsbebe-redo-mcp.service` are **byte-identical** to `deploy/systemd/buttonsbebe-{gorgias,redo}-mcp.service` (verified: `diff` exit 0, 2026-09-16). Same pattern for KB (`kb/buttonsbebe-kb-mcp.service` vs `deploy/systemd/buttonsbebe-kb-mcp.service` — sibling analyst's scope, same verdict applies). AGENTS.md:94 names `deploy/systemd/` as the home of systemd units. No test references the unit paths, and the CD manifest's REQUIRED_FILES for `tools` does not include them (`deploy/cd/source_release.py:33`), so the `tools/` copies are unreferenced documentation at drift risk.
4. **Launcher twins** — `tools/run-gorgias.sh` / `tools/run-redo.sh` differ only in module name and doc line; 4 lines each; intentional (per-module ownership, `tools/README.md:14-17`). Not actionable.

Vs other modules:

5. **Three Gorgias adapters, different safety domains** — `tools/gorgias_mcp.py` (Hermes read path, sync `requests`), `webhook/src/bb_webhook/gorgias_client.py:64-126` (human-gated writes, async `httpx`), `console-src/helpdesk-agent/bridge/gorgias_api.py:1-65` (dormant preview bridge, stdlib `urllib`). They **do not agree** on: User-Agent (`ButtonsBebe-Hermes/1.0` `gorgias_mcp.py:32` vs `ButtonsBebe-Dashboard/1.0` `gorgias_client.py:40` vs `DemoHelpdesk-GorgiasBridge/1.0` `gorgias_api.py:16`), timeout (20 s / 15 s `gorgias_client.py:39` / 30 s `gorgias_api.py:59`), auth construction (tuple / tuple / hand-rolled base64 `gorgias_api.py:28-31`), error shape (error-dict / `None`+`log_event` / `raise RuntimeError` `gorgias_api.py:64`). The genuinely shared logic is one f-string URL per adapter and the `/api` prefix. **Honest recommendation: duplication here is the deliberate safety boundary — three runtimes (tools/.venv, webhook uv env, stdlib-only bridge) and three blast radii; extracting a shared client would couple the Hermes read path to the write path's dependency tree for ~10 saved lines. Do not extract.**

Consequence: edits land in a file the repo deleted on 2026-09-16 when it merged CLAUDE.md into AGENTS.md (AGENTS.md:3-5; git status shows `D CLAUDE.md`) — the true source of truth (`AGENTS.md`) silently diverges from what the live brain was told to maintain. Evidence: `hermes/SOUL.md:24-26`. Fix: re-point both lines at `AGENTS.md` in the mirror **and** on the VPS copy (the repo edit alone doesn't fix production — the mirror is a copy).
2. **Mirror rot, instance 2 — skill/tool drift. [Resolved in Wave 1, PR #28: `SKILL.md` now lists all five tools including `list_recent_tickets`.]** `hermes/skills/buttonsbebe/gorgias/SKILL.md:17-20` lists four Gorgias tools and omits `list_recent_tickets`, which the service actually exposes (`tools/gorgias_mcp.py:73`) and which `SOUL.md:20` does list. 3. **Redo path-segment parameters reach the URL unvalidated.** Scenario: prompt-injected ticket content convinces Hermes to call `get_return(return_id="../orders")` or `get_order` with a crafted name (`tools/redo_mcp.py:125` `f"/returns/{return_id}"`, `:146` `f"/orders/{clean}"` where `clean = order_name.lstrip("#").strip()` `:135`). Consequence: the request path escapes its segment; still a GET within *our* store's URL base (`BASE` pins the store, `redo_mcp.py:32`) and the API key scopes reads, so the realistic worst case is a 404/error-dict — but this is an input-validation **asymmetry**: the same module family validates the Gorgias cursor defensively (`tools/gorgias_mcp.py:100-102`, tested at `tools/test_gorgias_read_contract.py:37-43`) and `StrictInt` guards every Gorgias id. (Cross-store reads being impossible is a hunch — not verified against Redo's router.) Minimal fix: one charset guard (`^[A-Za-z0-9_-]{1,64}$` → `ValueError`) mirroring the cursor guard, on both sites.
4. **Credential rotation requires the documented restart dance.** `_common.load_env` runs at module import (`tools/gorgias_mcp.py:44-49`, `tools/redo_mcp.py:29-32`), so rotated keys are invisible until restart. This is handled procedurally — the runbook explicitly lists restarting `gorgias-mcp`/`redo-mcp` after key rotation and consolidation (`deploy/ENV-CONSOLIDATION-RUNBOOK.md:95-99,134,136`). Failure mode if skipped is fail-soft and visible: every tool call returns `{"error": "Gorgias API 401" …}` to Hermes (`gorgias_mcp.py:66`), degrading drafts rather than crashing the service. **Already mitigated; no code action** — module-level loading is also what keeps secrets out of per-call paths and inside the authenticated service boundary (AGENTS.md §2.2).
5. **No retries on transient provider 429/5xx** (`tools/gorgias_mcp.py:63-69`, `tools/redo_mcp.py:41-49` single-shot). Consequence: a provider blip turns into an error dict; Hermes' own tool-loop guardrails warn after repeated same-tool failures (`hermes/config.example.yaml:89-99`) and the human sees a degraded draft in the console. For a one-shot-per-ticket read path this is the boring, correct choice (the write-path webhook client does honor `Retry-After` — `webhook/src/bb_webhook/gorgias_client.py:46-49,218` — a deliberate asymmetry: writes deserve retries, draft-context reads don't). **No action.**
6. **Long-running server**: not a risk in-repo — uvicorn/starlette under the SDK, systemd `Restart=on-failure` (`tools/buttonsbebe-gorgias-mcp.service:12-13`), localhost-only bind (`:9` `GORGIAS_MCP_HOST=127.0.0.1`). The Gorgias WAF-vs-default-urllib-UA issue is already handled by the explicit UA (`tools/gorgias_mcp.py:14,32`).

## Rejected on principle

- Shared low-level Gorgias client across the three adapters — three runtimes and three blast radii are the safety boundary; they don't agree on UA/timeout/error shape and shouldn't have to (`gorgias_mcp.py:32` vs `gorgias_client.py:39-40` vs `gorgias_api.py:16,59`).
- Hand-rolled `http.server` transport or any protocol-layer rewrite — the official MCP SDK is already the transport, JSON-RPC, and dispatch layer (0 hand-rolled protocol LOC measured).
- Merging Gorgias + Redo into one MCP service to deduplicate `_get` — per-module isolation is the stated architecture (`tools/README.md:3-6`); 11 boring duplicated lines is cheaper than the coupling.
- A retry/backoff dependency (e.g. tenacity) — read-only draft-context reads fail soft by design; retries belong to the write path, which already has them (`gorgias_client.py:46-49`).
- Replacing `requests` with `httpx` to match the webhook — no feature gain in a sync single-consumer service; churn in a pinned, hash-locked venv (`tools/requirements.lock`).
- Extracting Redo's `_trim` alias table (`tools/redo_mcp.py:61-88`) to config/data — it's the tested contract (`tools/test_tool_contracts.py:50-77`) and boring code; data-driving it adds a file.
- Deleting the `run-*.sh` launchers in favor of quoted `ExecStart` python paths — they are REQUIRED_FILES in the CD contract (`deploy/cd/source_release.py:33`) and the units point at `/root/*-mcp-run.sh` (`tools/buttonsbebe-gorgias-mcp.service:11`); 8 LOC, documented, zero churn wins.
