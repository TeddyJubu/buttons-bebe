**Interface/seam:** `git push` → GitHub Actions `verify` workflow runs the identical offline gate (`bash tools/verify_release.sh`, ci.yml:57) plus a `whatsapp` job (npm ci + npm test, ci.yml:59-72) → on whole-workflow success of a push event (deploy-production.yml:19-20), `git archive` + virtual `.buttonsbebe-release.json` (commit + generation = run_number, :35-36) → restricted SSH wrapper that only permits `deploy <sha40> <sha256>` (`deploy/cd/buttonsbebe-deploy-ssh.sh`) → receiver. The receiver re-validates everything the gate cannot prove from outside: archive size/digest (receive.sh:37-45), tar safety (embedded validator, :46-79), metadata commit match (:116-121), approved-config SHA256 fingerprints for `deploy/systemd` + `deploy/caddy` (exit 78 on drift, :98-113), applied-config fingerprints incl. required applied files (:134-138), then per-file atomic swap (mkstemp+fsync+os.replace, source_release.py:65-92), readiness probes per service (receive.sh:152-175), trap-based journal rollback (:226-247), timer pause/restore (:250-285). **The gate runs in CI before the swap; the receiver runs after it and trusts nothing but fingerprints** — (b) answered: per-file atomic, whole release explicitly NOT atomic (receive.sh:2-3), journal+trap rollback, hard-kill recovery documented (cd/README.md:84-89).

**Job:** turn every green push to `main` into a safe production swap on the VPS with zero interactive steps, keep Caddy/systemd config under fingerprint discipline, watch the fleet (heartbeat dead-man's switch + read-only ops monitor), and keep one runnable recovery path for each failure mode (journal rollback, caddy fragment rollback, warehouse safety patch rollback).

## Reliability risks

Gate-coverage gaps first.

1. **Real-Caddy contract tests never run in CI.** The three suites that `caddy adapt` + `caddy run` the actual fragments skip unless the binary exists: `deploy/tests/test_inbox_caddy_contract.py:41`, `test_receiving_caddy_contract.py:19`, `test_rewrite_maintenance.py:73` (`skipUnless(shutil.which('caddy'))`); CI installs only ripgrep (ci.yml:47-48). *Scenario:* a behaviorally wrong `support.caddy` edit lands on `main`. *Consequence:* gate passes on string assertions alone (`deploy/tests/test_caddy_config.py`); the error surfaces at deploy time, not PR time — though it cannot silently reach production because the receiver refuses unapproved config (exit 78, receive.sh:98-113) and the operator procedure requires `caddy validate` (deploy/caddy/README.md). *Minimal fix:* add `caddy` to the apt-get line (ci.yml:48) — one word — or accept the skip messages' documented "run this suite on Linux staging" status quo.
2. **Untracked ops scripts' tests never run in CI.** `tools/ops/backfill_ticket_status.py` (imports production normalizer `bb_webhook.webhook_handler._normalize_ticket_status`, :22) and `tools/ops/reparse_ticket_tags.py` (:20) are untracked, so CI's checkout lacks them and their tests; the gate would run them (`discover -s tools -p 'test_*.py'`, verify_release.sh:171) only once tracked. *Scenario:* a regression in the shared normalizer signature breaks a backfill. *Consequence:* no CI signal; 566 LOC invisible to review. *Fix:* commit them (they are read-only/fill-only by design and synthetic-tested) or delete if the backfill is complete — hunch: GORGIAS-FLAGS-TASKLIST entries 3/6 describe this schema work, so committing is the likely right answer.
3. **Root `shopify/` module absent from gate syntax roots** (verify_release.sh:85). Its test runs in the gate (:172-175) and imports the module, so imported files are covered; anything the test doesn't import would pass the gate, but CD ships no `shopify` component (REQUIRED_FILES, source_release.py:27-37) so it can't reach production via CD. Minor, labeled.
4. **Heartbeat status contradiction between two live docs.** `deploy/LOCAL-MONITOR.md:46-47`: heartbeat is "a separate legacy WhatsApp notifier and remains disabled unless separately reviewed/enabled" vs `AGENTS.md:196-197`: heartbeat dead-man's switch is listed as live, with install doc. *Scenario:* operator reads LOCAL-MONITOR, concludes there is no dead-man's switch. *Consequence:* a hung (not crashed) processor — which `Restart=on-failure` cannot catch and no unit has `WatchdogSec` (verified: zero occurrences across deploy/systemd/) — goes undetected; heartbeat.sh:146's work-marker check is the only work-stall detector. *Fix:* one-line correction to LOCAL-MONITOR.md:46-47.
5. **Dangling doc pointer in the root truth.** `AGENTS.md:282` references `deploy/GORGIAS-BRIDGE-SETUP.md`, which does not exist (also `helpdesk-design/INTAKE.md:8`; already tracked in `docs/simplification/12-gorgias-bridge.md:129`). *Fix:* belongs to the bridge module — create it or drop the pointer.
6. **Warehouse safety patch is anchor-brittle by necessity.** `deploy/warehouse/safety_patch.py` patches `/opt/warehouse/src/{server,shopify}.js` — an app maintained outside this repo, so runtime patching is the only repo-side mechanism (README.md documents this). `replace_once` (:162-168) aborts if an anchor matches ≠1 time, so upstream drift fails **closed** (availability loss of the guard, not a security hole). Answer to (a): a guarded, documented, dry-run-by-default, gate-tested **standing workaround** — acceptable here, not an anti-pattern; not replaceable by "fix the source" from this repo.
7. **Zero-hardening units.** 8 of 17 services have no hardening lines at all (gorgias-mcp, redo-mcp, kb-mcp, kb-admin, whatsapp-connect, kb-learn, kb-notices-gc, kb-sync); 13 units run as root (no `User=`); zero `WatchdogSec` anywhere. *Consequence:* any service compromise is a root compromise. *Fix:* copy the processor's 10-line block (deploy/systemd/buttonsbebe-processor.service:20-29) into the 8 units — mechanical, P3, single-tenant VPS lowers severity.
8. **Whole-release non-atomicity (documented, accepted).** Per-file atomic, release not (receive.sh:2-3); a hard kill mid-swap leaves mixed versions until journal rollback (trap) or manual `rollback --journal PATH` (cd/README.md:84-89). No cheaper mechanism exists that preserves the fingerprint discipline; see Rejected.

## Rejected on principle

- **Any new dependency.** Nothing meets the ≥100-LOC bar; the CD core (~700 LOC) is fingerprint discipline + journal rollback + tar-safety that no package provides.
- **systemd `WatchdogSec` instead of `heartbeat.sh`.** Would need `sd_notify` across three runtimes (Python/Node/bash) and only detects process-level hangs — heartbeat.sh:146 checks *work-completion* markers and delivers WhatsApp alerts out-of-band; systemd can do neither. The hand-rolled dead-man's switch is the right tool; its only defect is the doc contradiction (Action 1).
- **Whole-tree atomic deploy (rsync `--delay-updates` / symlink swap).** The journaled per-file swap is tested (`deploy/tests/test_receiver_recovery.py` runs in CI Linux; `test_source_release.py`), documented (cd/README.md:84-89), and a tree swap would break the applied-config fingerprint and mixed-timer pause/restore model. receive.sh:2-3 states the trade openly.
- **Merging `heartbeat.sh` + `monitor.py`.** Different jobs (alerting + latch vs read-only ops JSON); the shared marker grep is ~5 LOC. Merging couples the alert path to the status path for zero deletions.
- **Removing the `whatsapp` CI job despite gate duplication (W6).** Hunch, labeled: its `npm ci` exercises the lockfile install the hermetic gate refuses to do (verify_release.sh:4). Cheap, harmless.
- **Making the gate non-hermetic** (installing all service deps to run more tests in CI) — the hermetic design is the point (verify_release.sh:4); the receiver re-validates what the gate can't.
- **"Just fix the source" for the warehouse app.** The app lives at `/opt/warehouse` outside this repo; `safety_patch.py` is the documented, fail-closed, gate-tested mechanism (deploy/warehouse/README.md).
- **Reinstating `webhook/Caddyfile`.** Header verified today: "RETIRED — DO NOT DEPLOY"; only supported source is `deploy/caddy/Caddyfile.redacted` (AGENTS.md:113-114).
- **Auto-pruning release journals.** cd/README.md:91 deliberately defers deletion until off-host retention exists; a cron GC now would risk the only rollback path.
